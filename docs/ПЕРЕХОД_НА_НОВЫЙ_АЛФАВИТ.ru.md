# Переход словаря на новый узбекский алфавит

**Составлено:** 4 ноября 2026 г.
**Статус:** оценка работ, не план к исполнению.

Реформа заменяет диграфы одиночными буквами с диакритикой: `Sh → Ş`,
`Ch → Ç`, `Gʻ → Ğ`, `Oʻ → Ō`. Буква `Ng` по проекту перестаёт быть
отдельной буквой алфавита.

> редакции, которая была известна на момент составления. Закон принят
> Законодательной палатой 7 июля 2026 г. и передан в Сенат; окончательные
> начертания и правила могли измениться. Начинать конвертацию до публикации
> официальной таблицы нельзя — переделывать придётся весь корпус.

## 1. Код: работа небольшая, и это было заложено заранее

`src/lib/uzbekCollation.ts` использует алфавит **как данные**. Диграфы
определяются по длине строки:

```ts
const DIGRAPHS = lowerAlphabet.filter((letter) => letter.length === 2);
```

Когда `Sh` станет `Ş`, диграфов просто не останется, и ветка их обработки
перестанет срабатывать сама собой. Сортировка, группировка по буквам и
панель навигации читают один и тот же список.

**Что меняется в коде:**

| Файл | Что сделать |
| --- | --- |
| `src/constants/alphabet.ts` | заменить массив `UZBEK_ALPHABET` на новый |
| `src/lib/uzbekCollation.test.ts` | переписать 12 тестов под новые буквы |
| `src/components/dictionary/AlphabetNav.tsx` | ничего — читает алфавит из констант |
| `src/app/dictionary/DictionaryClient.tsx` | ничего |

Якоря разделов уже сделаны по **индексу** буквы (`harf-0`, `harf-1`, …), а не
по самой букве — именно потому, что `Oʻ` и `Gʻ` непригодны для адресной
строки. Ссылки на разделы переживут реформу без изменений.

**Оценка: 1 рабочий день**, включая тесты.

## 2. Данные: здесь основная работа

Измерено на корпусе 04.11.2026:

| | |
| --- | --- |
| Терминов | 1190 |
| Символов в заголовках | 28 037 |
| Символов в определениях | 1 148 182 |
| **Заголовков, которые изменятся** | **550 из 1190** |

Вхождения, подлежащие замене:

| Форма | В заголовках | В определениях |
| --- | --- | --- |
| `Sh / sh` | 376 | 20 207 |
| `Ch / ch` | 169 | 7 261 |
| `Oʻ / oʻ` | 142 | 9 105 |
| `Ng / ng` | 130 | 9 424 |
| `Gʻ / gʻ` | 55 | 1 647 |

Около **47 600 замен**. Механически — минуты. Проблема в том, что часть из
них будет неверной.

### 2.1. Что сломает слепая замена

1. **Русский и английский текст внутри определений.** Определения содержат
   переводы вида `(ing. Congress of Aix-la-Chapelle; rus. Ахенский конгресс)`.
   Замена `ch → ç` превратит `Chapelle` в `Çapelle`. Конвертер обязан
   различать языковые фрагменты, а не идти по всему полю подряд.

2. **Имена собственные и заимствования.** `Churchill`, `Washington`,
   `Shevardnadze`, `Schengen` — вопрос не технический, а редакционный:
   решает заказчик, транслитерируются ли они. Список таких случаев нужно
   собрать и утвердить **до** конвертации.

3. **Четыре разных апострофа в корпусе.** Правильный для `Oʻ`/`Gʻ` —
   U+02BB `ʻ`, но он встречается лишь 30 раз из 251:

   | Символ | Код | В заголовках |
   | --- | --- | --- |
   | `‘` | U+2018 | 197 |
   | `ʻ` | U+02BB | 30 |
   | `’` | U+2019 | 23 |
   | `'` | U+0027 | 1 |

   Сортировка это переживает — `uzbekCollation` приводит варианты к одному, —
   но конвертер, ищущий `oʻ`, пропустит 221 случай из 251. **Нормализация
   апострофов — обязательный первый шаг.**

4. **Кириллические буквы, неотличимые от латинских.** Три заголовка и 21
   слово в определениях: `Aaxen kоngressi` (кир. `о`), `Ad hoс` (кир. `с`),
   `SЕАТО` (кир. `Е`). Их надо вычистить до конвертации, иначе они дадут
   невидимый мусор.

5. **`ng` — не всегда буква.** В сочетаниях вроде `Vashington`, `Kongress`
   это `n` + `g`, а не отдельная буква алфавита. Сейчас это уже влияет на
   группировку, а при реформе потребует отдельного решения.

### 2.2. Порядок работ по данным

1. Нормализовать апострофы к U+02BB — скрипт, полчаса.
2. Вычистить кириллические подмены — скрипт плюс глазами, полчаса.
3. Собрать и утвердить список имён собственных, которые не транслитерируются.
4. Добавить в модель поля `title_old` и `definition_old` — исходное написание
   сохраняется, а не затирается. **Миграция без возможности отката
   недопустима.**
5. Конвертер с разбором языковых фрагментов, прогон на копии базы.
6. Отчёт о расхождениях: что изменилось, где конвертер не был уверен.
7. **Вычитка филологом.** Это не формальность: при 1190 статьях и
   внимательном чтении 60–100 статей в час получается 12–20 часов работы
   специалиста, и это не работа программиста.

## 3. Поиск во время переходного периода

Несколько лет люди будут набирать оба написания. Поиск по `shartnoma`
обязан находить `şartnoma`, и наоборот.

Решение — нормализующий слой: запрос и индексируемое поле приводятся к
единому «бесписьменному» виду (`ş → sh`, `ç → ch`, `ğ → g'`, `ō → o'`), по
нему и идёт сравнение. Сейчас поиск в
`SearchDiplomaticTermView` делает простой `icontains` по `title` и
`definition` — потребуется поле `search_key`, заполняемое при сохранении.

**Оценка: 1–2 дня** вместе с переиндексацией корпуса.

## 4. Переключатель написания (необязательно)

Показывать словарь в старом или новом алфавите по выбору читателя. Нужен,
если академия хочет обслуживать и тех, кто ещё не перешёл.

Реализуется поверх сохранённых полей `*_old` из пункта 2.4: переключатель в
шапке плюс выбор поля при рендеринге. Отдельного хранения не требует.

**Оценка: 3–5 дней** вместе с SEO (каноническая ссылка на одно написание,
чтобы не плодить дубли страниц).
