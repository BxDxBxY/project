# Техническая характеристика платформы «Диплoматический толковый словарь»

Документ подготовлен для передачи техническим специалистам (АТ-центр УМЭД) при
запросе серверных ресурсов. Дата: 11 сентября 2026 года.

> Раздел «Измеренные показатели» содержит результаты реального нагрузочного
> тестирования фронтенда, а не оценки. Методика измерений приведена в конце.

---

## 1. Состав системы

| Компонент | Технология | Примечание |
|---|---|---|
| Пользовательский интерфейс | Next.js 15.5.9, React 19.1.0, TypeScript 5.9.3 | SSR + статическая генерация + ISR (перегенерация раз в час) |
| UI-библиотеки | MUI 7, Tailwind CSS 4 | — |
| Редактор статей (админ-панель) | TipTap 3 | форматирование, изображения, ссылки |
| Мобильная оболочка | Capacitor 7 (Android/iOS) | каркас готов, сборка приложения — следующий этап |
| Серверная часть | Python 3.12, Django 5.1, DRF | данные предоставлены разработчиком бэкенда |
| База данных | PostgreSQL 16 | — |
| Обратный прокси | Nginx | завершение TLS, раздача статики |
| Контейнеризация | Docker + Docker Compose | — |

Внешние сервисы: Google reCAPTCHA v3 (защита формы обратной связи, загружается
только при начале заполнения формы) и Google Analytics 4 (только после согласия
пользователя на cookie).

## 2. Структура страниц

Публичная часть: главная, «О словаре», словарь (список всех терминов),
страница термина, контакты, три правовых документа (условия использования,
политика конфиденциальности, политика cookie), страница 404.

Служебная часть (`/admin`, закрыта авторизацией): панель статистики, управление
терминами, категориями, обращениями и пользователями.

Языки интерфейса: узбекский (по умолчанию) и русский. Английская версия —
в плане развития.

## 3. Измеренные показатели производительности

**Стенд:** 4 vCPU, 16 ГБ RAM, Linux, продакшн-сборка Next.js, база и API на том
же хосте, 1 191 термин в базе. Инструмент: autocannon, 50 одновременных
соединений, 10 секунд на сценарий.

| Страница | Запросов/с | Задержка p50 | Задержка p97,5 | Ошибок |
|---|---|---|---|---|
| Главная (статическая) | 868 | 54 мс | 90 мс | 0 |
| «О словаре» (статическая) | 965 | 50 мс | 75 мс | 0 |
| Словарь — список 1 191 термина | 417 | 116 мс | 175 мс | 0 |
| Страница термина (с запросом к API) | 130 | 369 мс | 532 мс | 0 |

**Потребление памяти процессом фронтенда:** 161 МБ в покое, пик 377 МБ при
50 одновременных соединениях.

**Вес страниц (HTML):** главная — 25 КБ, страница термина — 24 КБ, список
словаря — 172 КБ (все термины на одной странице).

**Размер артефактов:** сборка `.next` — 285 МБ, зависимости `node_modules` —
918 МБ (в Docker-образе оба слоя ужимаются).

## 4. Сколько пользователей выдержит

Пересчёт измерений в одновременных пользователей делается через время
«обдумывания»: читатель словаря открывает новую страницу примерно раз в 20–30
секунд.

| Сценарий | Расчёт | Результат |
|---|---|---|
| Самая тяжёлая страница (термин с запросом к API) | 130 запросов/с × 25 с | ≈ 3 000 одновременных читателей |
| Список словаря | 417 запросов/с × 25 с | ≈ 10 000 одновременных читателей |
| Статические страницы | 868–965 запросов/с × 25 с | свыше 20 000 |

**Осторожная рабочая оценка.** Теоретический предел снижаем минимум втрое —
на реальную БД под нагрузкой, конкуренцию с другими сервисами, антивирус и
резервное копирование. Даже так на 4 vCPU платформа уверенно обслуживает
**800–1 000 одновременных активных пользователей**.

Планируемая нагрузка значительно ниже: 200–300 одновременных пользователей в
обычном режиме, до 500 в пиковые периоды (сессия, конференции, мероприятия МИД),
3 000–5 000 посещений в сутки. **Запас по отношению к планируемой нагрузке —
не менее чем трёхкратный.**

Запрашиваемая конфигурация (8 vCPU / 16 ГБ) выбрана не «впритык», а с учётом:
мобильного приложения, публичного API для сторонних систем, роста базы терминов,
добавления аудиопроизношения и английской версии.

## 5. Что ограничивает производительность

1. **Страница термина** — самая тяжёлая: каждый просмотр идёт в API и базу.
   Ускоряется кэшированием на стороне Next.js и индексами в PostgreSQL.
2. **Список словаря** отдаёт все 1 191 термин одной страницей (172 КБ HTML).
   При росте базы свыше ~3 000 терминов потребуется постраничный вывод или
   виртуализация списка.
3. **Общий хост для фронтенда, API и базы.** При росте нагрузки первым узким
   местом станет PostgreSQL, а не Next.js.

| Показатель | Минимум | Рекомендуется |
|---|---|---|
| ОС | Ubuntu Server 22.04 LTS | Ubuntu Server 24.04 LTS |
| vCPU | 4 | 8 |

| Swap | 2 ГБ | 4 ГБ |

Распределение диска (рекомендуемый вариант, 200 ГБ): ОС и системные пакеты —
15 ГБ, образы и контейнеры Docker — 25 ГБ, база данных — 20 ГБ, медиафайлы —
30 ГБ, журналы — 10 ГБ, резервные копии за 30 дней — 50 ГБ, свободный резерв —
50 ГБ.

## 7. Сеть и доступы

- открытые порты 80 и 443 наружу; 3000, 8000, 5432 — только внутри сервера;
- SSH (22) по ключу, с ограничением по списку IP-адресов;
- субдомен в зоне `uwed.uz` (например, `lugat.uwed.uz`);
- сертификат TLS (Let's Encrypt или корпоративный), протоколы TLS 1.2/1.3;
- статический внутренний IP-адрес;
- доступ к SMTP-релею для уведомлений с формы обратной связи;
- возможность вертикального расширения ресурсов без миграции.

## 8. Нормативные основания размещения внутри страны

- Требования к официальным веб-сайтам государственных органов: регистрация в
  зоне **.UZ** и размещение на сервере **на территории Республики Узбекистан**.
- Закон «О персональных данных» № ЗРУ-547 (в редакции № ЗРУ-1125 от 26.03.2026):
  порядок обработки и хранения данных, регистрация базы персональных данных в
  Государственном реестре.

Размещение на серверах университета закрывает оба требования.

## 9. Методика измерений

```
# запуск платформы в продакшн-режиме
npm run build && npx next start -p 3000

# нагрузочный тест каждой страницы
npx autocannon -c 50 -d 10 http://localhost:3000/<страница>

# потребление памяти под нагрузкой
ps -o rss= -p $(pgrep -f next-server)
```
